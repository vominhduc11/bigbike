### B.3 🔴 Blocker (chi tiết đầy đủ)

**[7.4] Sales / Customers** — `src/screens/CustomerDetailScreen.jsx:136-147, 262-270`

- **Vấn đề:** Account-status change is broken. The shadcn/Radix Select fires onValueChange with the selected value STRING (e.g. "BLOCKED"), but handleStatusChange treats its argument as a DOM event and reads e.target.value (line 139), which is undefined. So changing a customer's account status submits undefined to updateCustomerStatus — the status update sends garbage / fails silently while still showing a success toast. Confirmed: Select = SelectPrimitive.Root, onValueChange has no event object. Contrast the correct credit Select at line 524 which uses onValueChange={(val) => ...}.
- **Đề xuất:** Change line 264 to onValueChange={handleStatusChange} -> onValueChange={(value) => handleStatusChange(value)} and update handleStatusChange to accept the value directly: async function handleStatusChange(value) { ... updateCustomerStatus(customerId, value) ... }. Then add a ConfirmDialog before applying, since BLOCKED/DISABLED are consequential account states (criterion 7.5).

### B.4 Chi tiết theo nhóm chức năng

#### Cross-cutting (hạ tầng dùng chung)

##### XC1 Routing & Navigation & IA  
_File: App.jsx, components/AdminShell.jsx, components/GlobalSearch.jsx, lib/useNavBadges.js, styles/admin-prototype.css_  
_6 phát hiện · 12 tiêu chí pass đã kiểm._

- 🟠 Major **[12.2]** `components/GlobalSearch.jsx:151-239` — The ⌘K command palette is built as role="dialog" aria-modal="true", but the result list has no listbox semantics. Rows are plain <button> inside a <div>, the keyboard-tracked active row (activeIndex) is not exposed via aria-activedescendant/aria-selected, and the input has no aria-controls/role=combobox. A screen-reader user pressing Arrow Down hears nothing change — the active highlight is purely visual (bg-surface-selected). This is the primary cross-module navigation entry point. _→ Sửa:_ Give the scroll container role="listbox" (id), each result button role="option" with a stable id and aria-selected={isActive}, and set role="combobox" + aria-expanded + aria-controls + aria-activedescendant={activeOptionId} on the <input>. This makes arrow-key navigation announceable per WCAG 4.1.2.
- 🟠 Major **[10.1]** `components/GlobalSearch.jsx:151-167` — The command-palette dialog has aria-modal="true" but no focus trap and no focus restoration. Tab can move focus out of the dialog to background page controls behind the overlay, and on close focus is not returned to the trigger button (line 140). Keyboard/SR users can get lost behind the modal. _→ Sửa:_ Trap Tab focus within the dialog while open (or reuse the shared layout/Modal primitive which already handles trap + restore), and on close() return focus to the trigger button via a ref.
- 🟠 Major **[10.1]** `components/AdminShell.jsx:171-242` — The mobile sidebar drawer (opened by the hamburger at ≤1024px) can only be dismissed by clicking the overlay or re-pressing the hamburger. There is no Escape-key handler and no focus management — focus is not moved into the drawer when it opens nor returned to the hamburger when it closes, and Tab is not trapped inside the open drawer. Keyboard users on tablet cannot reliably operate the off-canvas nav. _→ Sửa:_ Add a keydown handler closing the drawer on Escape, move focus to the first nav link (or sidebar container) when sidebarOpen becomes true, restore focus to the hamburger on close, and trap Tab within the drawer while open.
- 🟡 Minor **[12.3]** `components/GlobalSearch.jsx:121-133` — Keyboard ArrowUp/ArrowDown moves activeIndex across the flattened result list but the active row is never scrolled into view. The list is capped at max-h-[52vh] with overflow-y-auto (line 184); with 3 groups × 5 rows the active selection can move below the fold and the user loses sight of what Enter will open. _→ Sửa:_ On activeIndex change, scrollIntoView({ block: 'nearest' }) the active option element (ref keyed by flatIndex), so keyboard selection stays visible.
- 🟡 Minor **[2.7]** `components/AdminShell.jsx:232-282` — Comment at line 233 states the hamburger is hidden on ≥900px, but admin-prototype.css shows it (and the off-canvas drawer) actually engages at max-width:1024px (lines 1061, 1123). On desktop ≥1024px there is no way to collapse the sidebar to widen the content area — collapse only exists implicitly as the mobile drawer plus a form-route-only focus mode. Criterion 2.7 (sidebar collapsible to expand content) is unmet for the normal desktop work surface, and the inline comment misdocuments the breakpoint. _→ Sửa:_ Either provide a desktop sidebar-collapse toggle (icon-rail mode) for all routes, or accept focus-mode as the substitute and correct the line-233 comment to ≤1024px so it matches the CSS breakpoint.
- 🟡 Minor **[11.3]** `App.jsx:272-274` — The route-level Suspense fallback for every lazily-loaded screen is a generic centered StatePanel (loading text), not a skeleton that mirrors the target layout (table/cards/form). Switching modules shows a content-less panel then a layout snap-in, causing perceived layout shift on every navigation. (Flagged here only as the module-specific call site; the generic-fallback decision is app-level.) _→ Sửa:_ Pass a layout-matching skeleton (e.g. AdminTable skeleton for list routes, FormField skeletons for detail routes) as the Suspense fallback keyed off route.name, instead of one generic StatePanel for all 40+ screens.

##### XC2 Error boundary & Perceived performance  
_File: components/ErrorBoundary.jsx, App.jsx, components/StatePanel.jsx, main.jsx, bigbike-admin/index.html_  
_5 phát hiện · 7 tiêu chí pass đã kiểm._

- 🟠 Major **[8.7]** `components/ErrorBoundary.jsx:28-30` — Fallback hiển thị `this.state.error?.message` thẳng cho người dùng ở MỌI môi trường. Criterion 8.7 yêu cầu thông báo thân thiện (không lộ chi tiết kỹ thuật) cho admin và chi tiết lỗi CHỈ hiện ở dev. Message của lỗi runtime React (vd 'Cannot read properties of undefined') là chuỗi kỹ thuật, rò rỉ ra production, không có hành động nghiệp vụ rõ. _→ Sửa:_ Luôn hiển thị câu thân thiện cố định (vd 'Vui lòng tải lại trang hoặc liên hệ kỹ thuật viên.') cho người dùng; chỉ render `error.message` khi `import.meta.env.DEV`. Giữ message thật trong console.error (đã có ở componentDidCatch).
- 🟠 Major **[8.7]** `components/ErrorBoundary.jsx:25-26` — Container fallback lỗi không có `role="alert"` (cũng không có aria-live). Criterion 8.7 yêu cầu fallback lỗi mang `role="alert"` để screen reader thông báo khi cây component sập và fallback thay thế. Tiêu đề chỉ là <h1> tĩnh, không được announce. _→ Sửa:_ Thêm `role="alert"` vào <div> fallback (dòng 26). Đây là sửa cấp module trên chính ErrorBoundary, độc lập với việc app-level chưa có per-region boundary.
- 🟠 Major **[11.4]** `bigbike-admin/index.html:13` — `#root` rỗng, không có placeholder loading inline trước khi React render. Criterion 11.4 yêu cầu chèn placeholder loading inline trong #root để tránh màn trắng ban đầu của Vite SPA (khoảng trống giữa lúc HTML parse xong và bundle React mount). Trên mạng chậm admin thấy trang trắng hoàn toàn. _→ Sửa:_ Đặt markup placeholder tĩnh (spinner/skeleton + nền theo token admin) bên trong `<div id="root">...</div>`; React sẽ tự thay khi mount. This diverges from the sibling AuditDetailDrawer, which correctly uses the shared Modal (Radix Dialog) and gets focus trap + Escape for free. _→ Sửa:_ Render the sheet through the shared `Modal` (components/layout, Radix Dialog) — it provides focus trap, Escape, overlay-click dismiss, role=dialog and a labelled title — or, if a bottom-sheet visual is required, add role="dialog" aria-modal="true" aria-label, a keydown Escape handler, and initial-focus management to the existing markup.
- 🟡 Minor **[6.2]** `screens/AuditLogListScreen.jsx:298-306` — On the desktop layout there are no filter chips summarising the active module / actor type / date-range filters. The results bar only appends the literal word from `auditLog.summaryFiltered` (e.g. "(đã lọc)") to the count, so an admin cannot tell at a glance WHICH filters are applied without re-scanning every Select and date field. (Mobile has a search chip + active count, but desktop has nothing equivalent.) _→ Sửa:_ Render dismissible filter chips above the table for each active non-default filter (module, actor type, search term, date range) reusing the shared FilterChips primitive, each chip clearing its own filter via `updateQuery({ ... }, { resetPage: true })`.
- 🟡 Minor **[6.8]** `screens/AuditLogListScreen.jsx:332-342` — The audit table header is not sticky while scrolling. AdminTable renders the shadcn `<Table>`/`TableHead` (components/ui/table.jsx, no position:sticky), and `.audit-table-wrapper` is plain `display:block` with no internal scroll, so the page scrolls and the legacy `.admin-table th{position:sticky}` rule does not apply here. With page size selectable up to 100 rows (line 228), the column labels scroll out of view on long pages. _→ Sửa:_ Add a sticky header for the audit list — e.g. wrap the table in a max-height scroll container and apply `position:sticky;top:0` to the `thead`/`th` (mirroring the existing `.admin-table th` rule, using `--admin-color-surface-muted` background), so the header stays visible at the 50/100 page sizes.
- 🟡 Minor **[10.5]** `screens/audit-log-list/AuditDetailDrawer.jsx:112-118` — The change-diff `<table>` header cells lack `scope="col"`. Without scope, screen readers cannot reliably associate the Field / Before / After header cells with their data columns, weakening the semantic-table requirement of WCAG SC 1.3.1. _→ Sửa:_ Add `scope="col"` to each of the three `<th>` elements in the diff table thead.
- 🟡 Minor **[10.5]** `screens/AuditLogListScreen.jsx:344-354` — The mobile card container declares `role="list"` but its direct children are AuditCard roots with `role="button"` (cells/AuditCard.jsx line 29), not `role="listitem"`. An explicit role="list" with non-listitem children makes screen readers either drop the list semantics or fail to announce item count, so the role provides no benefit and may mislead. _→ Sửa:_ Either remove `role="list"` (and rely on the aria-label group), or wrap each card in a `role="listitem"` element so the list/listitem structure is valid while keeping the button affordance on the inner card.
- 🟡 Minor **[10.4]** `screens/audit-log-list/cells.jsx:57-59` — In ActionLabel the warning glyph `⚠` carries `aria-label={label}`, which duplicates the action label text rendered immediately after it as a sibling text node — so a screen reader announces the action name twice for every dangerous row. This is also inconsistent with AuditCard, where the same glyph uses `aria-hidden="true"`. _→ Sửa:_ Make the decorative glyph `aria-hidden="true"` (matching AuditCard) and convey "dangerous" via accessible text if needed (e.g. a visually-hidden label), rather than re-labelling it with the action name.

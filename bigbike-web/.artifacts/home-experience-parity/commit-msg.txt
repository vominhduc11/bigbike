refactor(bigbike-web): migrate home experience section to inline Tailwind

Migrate the Experience section leaf styling to inline Tailwind and strip the
matching bb-* rules from globals.css (-213 lines). Kept as markers/mechanism:
.bb-experience/.bb-experience--home (HeaderUiContext IntersectionObserver +
experience-section.spec), .bb-exp-carousel + .bb-exp-slide-link (e2e), and the
cover/content scale+opacity rules that react to .swiper-slide-active.

Migrated: section bg/color/padding, header align+padding, title, desc, slide
title, slide link, carousel padding, slide-content margin/padding. Dropped the
no-op .bb-exp-slide / .bb-exp-product-image classes. The <=767 dark->light
reskin layers collapse to the light values; the slide title stays white at
<=767 (it overlays the cover image band).

Notes / gotchas:
- carousel padding-bottom needs `!` - Swiper's unlayered `.swiper{padding:0}`
  beats a layered utility (old `.bb-home .bb-exp-carousel` won by specificity).
- font-size via CSS var needs `text-[length:var(...)]` (bare `text-[var(...)]`
  is parsed as a color, falling back to 16px).
- slide-content mt tiers use `max-[768px]:`/`max-[375px]:` (both arbitrary) so
  the smaller-max -14% wins at <=374; `max-md:` sorts before `max-[375px]:`.
- slide link uses `font-[family-name:var(--bb-font-cta)]` (not `.font-cta`) so
  the global `a:not(.font-cta):hover` red-hover is preserved.

A/B computed-style probe: 0 mismatches across
360/374/375/390/600/767/768/1023/1024/1280/1536/1920/2560.

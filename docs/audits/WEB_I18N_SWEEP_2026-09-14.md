# Storefront VI/EN audit — 2026-09-14

## Scope and evidence

Owner requested correction of the remaining gender labels, then a whole-web audit of the same
language-switch issue, fixes and a rebuild with `.env.vps`.

Canonical basis: `docs/engineering/ARCHITECTURE.md` (i18n rendering, locale URLs and UI messages),
`docs/engineering/API_CONTRACT.md` (variant option presentation, Catalog Facets, public review
photos), `docs/business/BUSINESS_RULES.md` (`PRODUCT_RULE_002`, `TRANSLATION_RULE_001/002`,
`REVIEW_RULE_005/016`), and `bigbike-web/STYLEGUIDE.md` (localized navigation and touch targets).

Reviewed 354 production TS/JS files under `app`, `components` and `lib` with source scans, the
existing i18n/copy guards and an additional AST inspection of 1,001 literal translation calls.
Manually classified Vietnamese source strings: localized branches/content dictionaries, analytics
identifiers, proper names/addresses, technical values and API-backed product content are not
automatically translation defects. Reviewed locale-aware data requests, query keys, date helpers,
auth/account/checkout labels and registered static route mappings.

Read-only runtime evidence after `docker ps` confirmed healthy web/backend/postgres:

- Public API `GET /api/v1/products/ao-bao-ho-cho-nu-ls2-airy-evo?lang=vi|en` and public-browser
  DOM both showed raw `Gender` in Vietnamese and `Nữ` in English. Product `wp-prod-33960` is live.
- `docker exec -i bigbike-postgres ... psql`, inside `BEGIN READ ONLY` / `ROLLBACK`, joined only
  catalog products, variants, options and attribute dictionaries. The `gender` dictionary has
  name `Gender`, no `name_en`, and `Nam`/`Nữ` values without English labels. Five currently
  published, non-discontinued products use it. No product/customer/order data was changed.
- Catalog facets already return `Nam`/`Nữ` for Vietnamese and `Male`/`Female` for English,
  preserving `Nam`/`Nữ` keys. No sidebar/chip correction was needed.
- Public browser reproduced `/en/review-invitations/unsubscribe/` → language switch to VI →
  `/review-invitations/unsubscribe/` → 404. Tested without any token or opt-out submission.

## Findings corrected

| Finding | Correction |
|---|---|
| Gender heading and choices used raw data in both locales | Reuse `Catalog.filterGender`; translate known `Nam`/`Male`, `Nữ`/`Female` only for recognized gender attributes. Raw selection keys/values and variant IDs are unchanged. |
| Longer English gender labels would overflow the old square choice | Allow gender buttons to grow horizontally using existing spacing tokens; retain height, selection and availability behavior. |
| Known color headings could retain legacy Vietnamese labels in EN | Use `Catalog.filterColor` for recognized color groups; do not invent translations of commercial color values. Existing size-heading fix is retained. |
| Review photos called absent `Product.reviews.photoAlt` | Add both translations with author and image index; test with real message catalogs. |
| Selecting too many review photos called absent `errorPhotoCount` | Add both translations, preserving the existing maximum of 10 photos. |
| Photo upload failures displayed raw backend-language text | Use localized upload/rate-limit messages; preserve API errors and validation. |
| Opt-out URL helper lacked its registered VI/EN mapping | Add the exact registered mapping, preserving query/hash; no change to opt-out confirmation. |
| Opt-out Home action always linked to VI; a linked homepage banner did not localize its product link | Reuse the existing locale-aware URL helpers. Tests cover VI/EN banner destinations and Home actions; external URLs and artwork stay unchanged. |

Added regression guards for literal translation-key references and parity between all registered
public static routes and the shared URL helper. Existing user changes elsewhere were preserved.

## Data-only observations and boundaries

- Read-only aggregate: 185 published, non-discontinued products; **0 missing English names**,
  **105 have a Vietnamese short description but no English short description**, and **0 have
  Vietnamese specifications HTML without English specifications HTML**. This is field-level
  fallback by `PRODUCT_RULE_002`, not a broken locale switch. No automatic translation or DB
  backfill was performed (`TRANSLATION_RULE_001`).
- English homepage/news cards also contain Vietnamese article text from stored-content fallback.
  Read-only `articles` aggregate: **160 published articles; 82 lack an English title and 94 lack
  an English body**. The current `cach-khu-mui-mu-bao-hiem` article has both fields missing.
  This follows `ARTICLE_RULE_002`; the language switch cannot supply absent editorial content.
  Excerpts may be derived from the fallback body. No article content was edited.
- The same dictionary audit found 79 used color values without `label_en`. These are commercial
  labels; they remain catalog-owned values, not a hardcoded web translation table. Size/model
  codes and brand/proper names are intentionally not mechanically translated.
- Banner images are shared assets. Text embedded in images cannot change through UI-message
  translation. The slider API also currently returns canonical product metadata without a lang
  parameter (controller/service evidence); no backend/slider API change or replacement artwork
  is included in this web-label patch. All five active banners currently have no linked product
  (`productLink`/`productName` are null), so there is no untranslated product caption from this API
  in the current banners. The future linked-banner navigation path is nevertheless corrected.
- This patch does not change persistence of manual, unlinked PDP choices across route changes.
  Linked `?variant=` choices are covered by regression tests.
- Signed-in account/order data, successful checkout, review uploads/submission and opt-out
  mutations were not exercised against real customer data. Coverage there is source/unit-based;
  browser audit is guest/read-only.
